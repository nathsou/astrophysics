The Calculus of Inductive Constructions is a mature, successful foundation: millions of lines of formalised mathematics and verified software rest on it. It is not the end of the story. Type theory is an active research field, and several of its most exciting directions start from questions CIC leaves open — above all, *what is equality?* This last chapter is a guided tour, with pointers for further reading.

## Equality, revisited

In Lean, equality is an inductive family in `Prop`, and because `Prop` is proof-irrelevant, any two proofs of `a = b` are equal. This principle is called **uniqueness of identity proofs** (UIP):

<Playground title="UIP holds in Lean — by rfl" code={`theorem uip {α : Sort u} {a b : α} (p q : a = b) : p = q := rfl`} />

Martin-Löf's intensional type theory, without proof irrelevance, does *not* prove UIP. Thomas Streicher showed in 1993 that UIP is equivalent to an extra elimination principle, **axiom K**, and Martin Hofmann and Streicher (1994) built a model — the *groupoid model* — where equality proofs can genuinely differ. In that model a type is not a set but a groupoid: elements with a *set of isomorphisms* between them, and a proof of `a = b` is one of those isomorphisms.

### Homotopy type theory

Vladimir Voevodsky, a Fields medallist working in algebraic topology, and independently Steve Awodey and Michael Warren, saw around 2006 that intensional type theory has a much richer interpretation: **types are spaces**, elements are points, and a proof of `a = b` is a **path** from `a` to `b`. Proofs of equality between proofs of equality are homotopies between paths, and so on up. The J eliminator of Chapter 13 is exactly *transport along a path*.

From this perspective Voevodsky proposed the **univalence axiom**: for types `A` and `B`, the type of equalities `A = B` is equivalent to the type of equivalences `A ≃ B`. Isomorphic structures are *equal*, so any construction automatically transports across isomorphisms — a principle mathematicians use constantly and informally. Univalence is incompatible with UIP (the type `Bool = Bool` has two different elements: the identity and negation), and hence with Lean's definitional proof irrelevance applied to equality in `Type`. **Homotopy type theory** (HoTT, *the HoTT book*, 2013) also adds **higher inductive types**: types generated by points *and paths*, such as the circle — one point and one non-trivial loop — which make synthetic homotopy theory possible inside type theory.

### Cubical type theory

Univalence stated as an axiom breaks canonicity: a closed term of type `Nat` built with it may be stuck. **Cubical type theory** (Cohen, Coquand, Huber and Mörtberg, 2015) fixes this by making paths primitive: a path is a function out of an abstract interval `I`, with endpoints `0` and `1`, and univalence becomes a *theorem* that computes. Function extensionality is trivial (a path between functions is a function into paths), and higher inductive types compute too. **Cubical Agda** implements it, and the `1lab` is a large library of mathematics written in it.

### Observational type theory

A different answer to "what is equality?": define it by *recursion on the type*. Equality of pairs is the pair of equalities of components; equality of functions is pointwise equality; equality of propositions is logical equivalence. This is **observational type theory** (Altenkirch, McBride and Swierstra, 2007), revived in recent years as *setoid type theory* and XTT. It validates function extensionality and propositional extensionality by definition, is compatible with definitional proof irrelevance — the Lean way — and retains canonicity. It is a plausible foundation for a future Lean-like system with fewer axioms.

## Other extensions

- **Strict propositions.** `SProp` (Gilbert, Cockx, Sozeau and Tabareau, 2019) is a sort of definitionally proof-irrelevant propositions added to Rocq and Agda alongside the ordinary, relevant ones — a way to get Lean's convenience while keeping decidable definitional equality elsewhere.
- **Induction–recursion and induction–induction.** Define a type together with a function on it (Dybjer's induction–recursion, used to build universes internally), or a type together with a family over it. Agda supports both.
- **Coinduction and guarded recursion.** Infinite data and processes, with termination replaced by *productivity*; guarded type theories use a "later" modality to make productivity a typing property.
- **Quantitative and linear type theory.** Track how many times each variable is used (Atkey, McBride; Idris 2). Erasure becomes a typing discipline rather than a `Prop`-based convention, and resources such as memory or file handles can be managed safely.
- **Two-level type theory.** An inner, homotopical type theory inside an outer, strict one, combining the benefits of both.
- **Modal type theories.** Type theories with modalities for time, space, cohesion or staging.

## Trusting the trusted base

The de Bruijn criterion reduces trust to the kernel. Current work reduces it further:

- **MetaCoq** formalises the metatheory of Rocq in Rocq and extracts a *verified* type checker.
- **Lean4Lean** re-implements Lean's kernel in Lean, with the goal of proving it correct; several independent Lean kernels (in Rust, Scala, Lean) can re-check Mathlib.
- **CakeML** and seL4 show that verified compilers and operating-system kernels, checked in HOL4 and Isabelle, are feasible — the same goal as the de Bruijn criterion applied to the whole software stack.

## Where to go from here

You now know what a Lean proof *is*: a term of CIC, checked by a kernel much like the one running in your browser. A good next step is to learn to write such terms at scale, with Lean's tactics and libraries:

- *Theorem Proving in Lean 4* — the official introduction to Lean as a proof assistant, with a precise account of its type theory;
- *Functional Programming in Lean* — Lean as a programming language;
- *Mathematics in Lean* — formalising mathematics with Mathlib;
- *The Hitchhiker's Guide to Logical Verification* — a course using Lean for program verification.

<History title="A young field">
The ideas in this chapter are recent: univalence dates from 2009, the HoTT book from 2013, cubical type theory from 2015, strict propositions from 2019. The Special Year on Univalent Foundations at the Institute for Advanced Study (2012–13) brought together type theorists, homotopy theorists and computer scientists, and the field has grown quickly since. Meanwhile formalised mathematics has moved from demonstrations to research practice: Mathlib contains over a hundred thousand definitions and a quarter of a million theorems, and new results are increasingly formalised as they are proved.
