If you can recognise a correct record of a computation, you can find the value of any computable function by *searching for its record*: test $s = 0, 1, 2, \ldots$ until $T(e, x, s)$ holds, then read off $U(s)$. Kleene’s normal form theorem says exactly this: $f(x) \simeq U(\mu s\, T(e, x, s))$, with $T$ and $U$ primitive recursive. From now on the book takes this equation as the *definition* of $\varphi_e$.

</Added>

## One search is enough

The definition of a partial recursive function may nest unbounded searches inside each other, inside compositions and recursions. The normal form replaces all of them by a single $\mu$ on the outside, applied to a primitive recursive relation. Every partial recursive function is a primitive recursive function ($U$) of a single search over a primitive recursive relation ($T$). The search is the only place where a computation can fail to end.

The book’s slogan: $\mu s\, T(e, x, s)$ *searches for a computation sequence of the function with index $e$ on input $x$, and $U$ returns its output if one can be found.* If $\varphi_e(x)\uparrow$, no record exists, the search never ends, and $U(\mu s\, T(e, x, s))$ is undefined — so the equation holds in the sense of $\simeq$.

## Is the least record special?

In this edition’s coding a computation has exactly one record (the computation is deterministic, and the record contains all of it). So the least $s$ with $T(e, x, s)$ is simply *the* record. In a coding where records could be padded with junk, $\mu$ would pick the smallest; any would give the same $U(s)$.

The literal search is hopeless in practice — records are enormous numbers — but it does not need to be practical. The theorem is about what can be computed, not how fast. The workbench runs it for the handful of computations whose records are small enough.

## Infinitely many indices

Every partial computable function has infinitely many indices: add a step that does nothing. In this edition’s coding, $\mathrm{Comp}(P^1_0; f)$ computes the same function as $f$ and has a larger index; do it again, and again. The book’s examples — “test if $0 = 0$, or count to $5$” — are the same idea.
