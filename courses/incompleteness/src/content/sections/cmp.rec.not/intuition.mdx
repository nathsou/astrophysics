Because the primitive recursive functions are generated by clauses, each one can be given a **name** that records how it was built: $\mathrm{zero}$, $\mathrm{succ}$, $P^n_i$, $\mathrm{Comp}_{k,n}[F, G_0, \ldots, G_{k-1}]$ and $\mathrm{Rec}_k[F, G]$. Names are finite strings, so they can be listed and numbered.

</Added>

## Notations

If $F$ names a $k$-place $f$ and $G_0, \ldots, G_{k-1}$ name $n$-place functions, then $\mathrm{Comp}_{k,n}[F, G_0, \ldots, G_{k-1}]$ names their composition. If $F$ names a $k$-place $f$ and $G$ a $(k+2)$-place $g$, then $\mathrm{Rec}_k[F, G]$ names the function defined by primitive recursion. Addition is

$$
\mathrm{Rec}_1[P^1_0, \mathrm{Comp}_{1,3}[\mathrm{succ}, P^3_2]].
$$

The subscripts are redundant — they can be computed from the parts — but they make the notation easy to check at a glance.

## Notations are not functions

A notation is a piece of syntax; the function is what it denotes. Many notations denote the same function: $\mathrm{Comp}_{1,1}[P^1_0, F]$ denotes the same function as $F$, for any $F$. This distinction becomes important in <Ref k="cmp:rec:npr:sec" />, where notations are numbered to list all primitive recursive functions — with repetitions, which, the book remarks, cannot be computably avoided.

## Numbers for notations

<Ref k="cmp:rec:npr:sec" /> assigns each notation a number with sequence codes, e.g. $\#(\mathrm{Rec}_l[G, H]) = \langle 4, l, \#(G), \#(H)\rangle$. The codes of the parts sit in exponents, so the numbers are astronomical — the workbench shows how large — but that does not matter: what matters is that coding and decoding are mechanical.
