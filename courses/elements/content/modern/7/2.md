---
title: Euclid's algorithm
---
**Statement.** Given two numbers $a, b$ that are not prime to one another, find their greatest common divisor $\gcd(a, b)$.

**Porism.** Every common divisor of $a$ and $b$ divides $\gcd(a, b)$.

**The algorithm.** Subtract the smaller number from the larger, again and again, and stop when the number left divides the one before it. In the figure, @CD taken twice from @AB leaves @EA; @EA taken from @CD leaves @CF; and @CF divides @AE. With the default sliders, $36 - 2 \cdot 15 = 6$, $15 - 2 \cdot 6 = 3$, and $3 \mid 6$. So $\gcd(36, 15) = 3$.

The process cannot reach the unit, because then $a, b$ would be prime to one another by [[7.1]]. The remainders decrease, so it has to stop somewhere, and it stops at a number that divides the one before.

**Proof.** There are two things to show.

1. *@CF is a common divisor.* Go back up the chain. $CF \mid AE$, so $CF$ divides $DF$, which is a multiple of $AE$. It divides itself, so it divides $CD = DF + FC$. So it divides $BE$, a multiple of $CD$, and then $AB = BE + EA$.
2. *It is the greatest.* Let $g$ (the dashed @G) divide both $AB$ and $CD$. Go down the chain. $g$ divides $BE$, so it divides $AE = AB - BE$. So it divides $DF$, and then $CF = CD - DF$. Something that divides $CF$ is not greater than $CF$.

Step 2 proves more than Euclid asks: every common divisor divides $CF$. That is the porism, and it is the form of the theorem that later propositions use ([[7.3]], [[7.33]]).

:::code Two loops, one invariant
Euclid's version uses subtraction only. The modern version replaces a run of subtractions of the same number by one division with remainder:

```ts
// Euclid's form (VII.1–2): subtract the smaller from the larger until they are equal.
function gcdSubtractive(a: number, b: number): number {
  while (a !== b) {
    if (a > b) a -= b;
    else b -= a;
  }
  return a;
}

// The division form: (a, b) → (b, a mod b) until the remainder is 0.
function gcd(a: number, b: number): number {
  while (b !== 0) [a, b] = [b, a % b];
  return a;
}
```

Both loops keep the same invariant: the *set* of common divisors of the pair never changes, because $e \mid x \wedge e \mid y \iff e \mid y \wedge e \mid x - y$. Both loops also have a variant that strictly decreases (the larger number, or $b$), so both terminate. Try $a = 144$, $b = 1$ in the widget: the subtractive form needs 143 steps, the division form one. Subtraction takes time proportional to the numbers themselves. Division takes time proportional to their number of digits.
:::

:::leads Where it leads
*The worst case.* Each quotient is at least $1$, so the remainders shrink at least as fast as Fibonacci numbers do in reverse. Consecutive Fibonacci numbers are the worst case: every quotient is $1$, and $(F_{n+1}, F_n)$ needs $n - 1$ divisions. Try $89, 55$ in the widget. Lamé (1844) turned this into a bound: the number of divisions is at most five times the number of decimal digits of the smaller number. This is one of the first results in the analysis of algorithms.

*Bézout.* If you run the division form backwards, you can write the gcd as a combination $\gcd(a,b) = ax + by$ with integers $x, y$ (the *extended* Euclidean algorithm). Euclid never does this. His substitute is the theory of least numbers in a ratio ([[7.20]]–[[7.22]]). But it is how modular inverses are computed today, for example the private exponent of an RSA key.

*Magnitudes.* The same subtraction applied to two lengths is [[10.2]] and [[10.3]]. For lengths the process may never end, and that is exactly Euclid's test for incommensurability.
:::

:::gap One run, not all runs
Euclid's text follows a run with exactly two remainders ("let @CD, measuring @BE, leave @EA…"), and the argument climbs up and down that particular chain. A modern proof is an induction on the number of steps, which is exactly the loop invariant above. Euclid proves general statements this way throughout Books VII–IX: he argues on a representative case and leaves the generalization to the reader. The figure builds @AB and @CD backwards from @CF, so that the run always has this shape. The widget shows runs of any length.
:::
