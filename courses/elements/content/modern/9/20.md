---
title: There are more primes than any given list
---
**Statement.** Prime numbers are more than any assigned multitude of prime numbers. In modern terms: *for every finite list of primes there is a prime not on the list.*

Euclid never says "there are infinitely many primes". Greek mathematics avoided the actual infinite. The theorem is about a finite list that someone hands you, and it gives a procedure that always produces one more prime. That the primes form an infinite set follows at once, but it is not how Euclid puts it.

**Proof (Euclid's).** Let the given primes be @A, @B, @C.

1. Let @DE be the least number that $A, B, C$ all divide. For distinct primes it is their product $P = ABC$.
2. Add the unit @DF, giving @EF $= P + 1$.
3. **Case 1:** $EF$ is prime. It is larger than each of $A, B, C$, so it is a prime not on the list.
4. **Case 2:** $EF$ is not prime. Then some prime @G divides it ([[7.31]]). Suppose $G$ were one of $A, B, C$. Then $G$ divides $DE$ and $EF$, so it divides their difference, the unit $DF$. No number divides the unit, so $G$ is not on the list.

Either way, a new prime has been found.

**What the proof is, and is not.** It is often retold as "suppose there are only finitely many primes, multiply them all, add one, contradiction". Euclid's version is direct: it starts from *any* finite list, not a supposedly complete one. The only reductio is the small one in step 4, which shows that $G$ is new. It also does not claim that $P + 1$ is prime, a common misreading. The case analysis is there because $P + 1$ often is not: for the list $2, 7$ it is $15 = 3 \cdot 5$, and for $2, 3, 5, 7, 11, 13$ it is $30031 = 59 \cdot 509$. The figure's default list $2, 5, 11$ gives $111 = 3 \cdot 37$.

As in many of Euclid's arithmetic proofs, the list has three members, standing for any number of them.

::euclid-primes{set="2,7"}

:::code The proof is an algorithm
```ts
// Given any finite list of primes, return a prime that is not on it.
function newPrime(primes: number[]): number {
  const n = primes.reduce((p, q) => p * q, 1) + 1; // DE + DF = EF
  for (let d = 2; d * d <= n; d++) if (n % d === 0) return d; // case 2: least prime factor G
  return n; // case 1: EF is prime
}
```
The invariant is `primes.every(p => n % p === 1)`: every listed prime leaves remainder 1, so none of them divides `n`, and so neither does any prime factor of `n`. The least divisor $d \ge 2$ of `n` is automatically prime ([[7.31]]'s descent).

Calling `newPrime` repeatedly, each time adding the result to the list, generates infinitely many distinct primes. Starting from $2$ it gives $3, 7, 43, 13, 53, 5, \dots$ (the Euclid–Mullin sequence). Try it with the widget's "add" button. The primes do not come in order, and it is unknown whether every prime eventually appears.
:::

:::leads Where it leads
Euclid's argument shows that there are infinitely many primes, but says little about how many there are below a bound. Euler proved more in the eighteenth century: the sum $\sum 1/p$ over the primes diverges. The prime number theorem (Hadamard and de la Vallée Poussin, 1896) says that the number of primes up to $x$ is asymptotically $x / \ln x$. Dirichlet (1837) proved that every progression $a, a + d, a + 2d, \dots$ with $\gcd(a, d) = 1$ contains infinitely many primes. For some progressions, such as $4k + 3$, a variant of Euclid's own trick is enough.
:::

## Try it without code

Start with the primes 2, 3 and 5. Their product plus one is 31. Now include 7, 11 and 13: the product plus one is 30031 = 59×509. Which part of the proof survives when the constructed number is composite? Its prime factors are still absent from the original list. The construction guarantees a new prime factor, not that the whole number is prime.
